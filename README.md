## Problem and role of data

The owner cannot see, in one place, which dummy products sell, which
channel sells most, or which stock is running low. Data answers that
by turning the dummy inventory/sales records into totals, channel and
product breakdowns, low-stock signals, and a baseline low-stock model
that other teams can consume as JSON. Real decisions must wait for
real data that the owner (Ade) decides to use; there is no external
approver to wait for.

## Business questions (answered on dummy data)

1. Which channel sells the most dummy units?
2. Which dummy products sell the most, and which run low on stock?
3. On which dummy days / weeks does stock run lowest?

## Run

```bash
pip install -r requirements.txt
python analysis/generate_dummy_data.py   # regenerates the dummy CSV (seed 42)
python analysis/wrangle_analyze.py       # -> outputs/business_summary.json
python analysis/baseline_model.py        # -> outputs/baseline_model.json
streamlit run dashboard/app.py           # interactive dashboard
```

## Data (dummy only, labelled)

- `data/dummy_inventory_sales.csv`: 600 rows, dummy dates
  2026-09-01 to 2026-09-30, 5 dummy products x 4 channel labels
  (Instagram, Facebook, Carousell, Shopee) x 30 days.
- `data/data_dictionary.md`: full column definitions, source
  (generated by `analysis/generate_dummy_data.py`, seed 42), and
  limitations. Channel values are labels only, not proof of a sale
  on that channel and not sync.
- Limitations: stock in the generator is shared across channels and
  channel order within a day is arbitrary, so per-channel stock rows
  are not a real channel-level stock ledger. There is no customer,
  order, payment, or shipping data in this dataset, by design.

## Data wrangling

`analysis/wrangle_analyze.py`: parses dummy dates, asserts no missing
values, derives dummy revenue (units x dummy price) and a low-stock
flag (stock_end <= 5), then aggregates by channel, product, and day.

## Findings and recommendations (dummy data only)

Verified by running `wrangle_analyze.py` on the dummy CSV:

- Total dummy units sold: 633. Total dummy revenue: Rp 203,667,000
  (dummy prices x dummy units; NOT real revenue).
- Units by channel (dummy): Facebook 178, Shopee 153, Instagram 152,
  Carousell 150. Facebook is highest in this dummy set.
- Units by product (dummy): Sepatu Sneakers Hitam (Contoh) 166,
  Sepatu Sneakers Putih (Contoh) 122, Sepatu Kasual Cokelat (Contoh)
  119, Sepatu Slip-On Abu (Contoh) 116, Sepatu Lari Ringan (Contoh)
  110.
- Low-stock rows (stock_end <= 5): 149 of 600 rows.
- Final dummy stock: DUMMY-001: 41, DUMMY-002: 35, DUMMY-003: 5,
  DUMMY-004: 127, DUMMY-005: 14.

Recommendations (dummy signal only, confirm with real data first):
1. Restock dummy products ending at low stock (especially DUMMY-003
   at 5) before they hit zero.
2. Focus restock checks on the highest dummy-unit channel, but do not
   treat the dummy ranking as a real channel ranking.
3. Keep one master inventory record so channel labels do not drift
   apart; do not add automatic sync in the prototype.

## Baseline model (no leakage)

`analysis/baseline_model.py`: predicts whether a product-channel week
will end in low stock next week (stock_end <= 5 in the following
week). Features come from the previous week only (week-start stock,
average daily units, price). Split is by time (train weeks < 38,
test weeks >= 38; train 40 rows, test 60 rows), and the scaler is
fitted on training data only, so no test information leaks into
training. Model: LogisticRegression baseline.

Verified results (dummy data):
- Accuracy (test): 0.7833
- Macro F1 (test): 0.7044
- Test positive rate: 0.2000

Limitation: dummy data only, tiny weekly sample (60 test rows), and
shared-stock generator quirks, so this baseline is a pipeline demo,
not a forecast to act on. The final version must retrain on
owner-decided data and compare models properly.

## Dashboard

`dashboard/app.py` (Streamlit): business indicators (total dummy
units, total dummy revenue, low-stock rows), channel and product
filters, daily dummy units chart, and a file-upload path to replace
the dummy CSV with a new file of identical columns for the session.
The dashboard is a skeleton for the final version: it does not yet
embed into the Full-Stack web app (embedding is still open work;
the agreed consumption point is `outputs/business_summary.json`
and the backend `/api/v1/insights` endpoint, which Phase 1 now
serves).

## How other teams consume the outputs

- Full-Stack: read `outputs/business_summary.json` for insights, or
  serve it via `/api/v1/insights` (Phase 1: done, see
  `API_CONTRACT.md`).
- Gen AI: use the dummy product/channel labels in
  `data/dummy_inventory_sales.csv` only as example context, never as
  real stock or prices.
- Data dictionary: `data/data_dictionary.md`.
